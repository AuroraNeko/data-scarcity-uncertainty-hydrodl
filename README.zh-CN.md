# 监督训练记录长度对径流预报点预测技巧与区间可靠性的影响

本仓库包含一项训练记录稀缺性研究的完整代码与数据流水线。研究回答两个
问题：径流预报深度学习模型每多一年测流记录能带来多少提升？它的 90%
不确定性区间要怎样才算达标？点预报技巧随记录稳定增长；区间覆盖率则
不然，靠的是在一小段保留窗口上重校准。

## 方法

![实验设计](docs/figures/design_timeline.png)

*每个模型只用 1995 年 9 月截点之前的最后 1、3、5 或 15 年标签训练。
校准窗（1995-2000）与测试期（2000-2008）对所有训练长度完全相同。*

**模型。** 所有实验共用同一个 LSTM 预报器。它每天读入之前 180 天的
气象驱动和静态流域属性，输出径流中位数预报以及包围它的 0.05/0.95
区间带。分位数（pinball）损失保证区间单调，上界不会低于中位数。

**问题。** 测流记录昂贵，许多流域只有几年观测，因此预报器是否需要
完整记录、短记录够不够用，是个有实际意义的问题。同一个模型在每个
流域、每个种子上各训练四次，分别只用截点前的最后 1、3、5、15 年
标签。截点之后的数据一律不参与训练。

**校准。** 神经网络的原始分位数区间通常达不到名义覆盖率，因此每个
模型都要经过 split conformalized quantile regression（CQR）重校准：
用 1995-2000 保留窗口量出区间差多少，再用一个常数把所有区间统一
加宽或收窄这个量。三种变体相互比较：全局单一修正、逐流域修正、
按预测流量分层修正。

**规模。** 主实验是 50 个 CAMELS-US 流域、每个 3 个训练种子。四个
互斥的 50 流域子集在 250 个独立流域上重复端点实验；671 流域基准
比较八种不确定性构造；另有 48 个拟合覆盖架构与协议敏感性（TCN、
13 分位数头、替代训练年份、365 天记忆）。标准 LSTM 作为单独的
架构对照复跑两个端点。每个报告的效应都附带同时重采样流域与
HUC2 分区的 bootstrap 区间。

## 关键结果

两张图概括主要发现，表格列出对应的数值。

**记录更长，精度更高，覆盖率仍不达标。** 一年监督记录的中位流域
NSE 为 0.511，十五年升到 0.666，区间质量也随之改善。但原始 90%
覆盖在任何训练长度下都低于名义值：一年 0.776，十五年 0.821。可见
只加长记录并不能让未校准的分位数变得可靠。

![监督训练记录长度的影响](docs/figures/fig1_scarcity_effects.png)

*监督训练记录长度与点技巧、区间行为的关系（50 个主流域）。技巧与
覆盖随记录增长；原始覆盖在校准前始终低于名义值 0.90。*

**校准才能恢复覆盖率。** 在 1995-2000 保留窗口上做 CQR 重校准后，
边际覆盖回到名义水平；再按预测流量分层修正，各流量组内部的覆盖也
得到恢复。原始区间欠覆盖最重的高预测流量组改善最明显。

![CQR 校准前后的条件覆盖](docs/figures/fig2_conditional_coverage.png)

*按预测流量分组的覆盖率，在保留校准窗口上做 CQR 重校准前后对比。*

| 结论 | 数值 |
|---|---|
| NSE 中位数 1年→15年 | 0.511→0.666;配对效应 0.140 [0.104, 0.173] |
| 原始 90% 池化覆盖 1年→15年 | 0.776→0.821;等流域效应 +4.6pp [1.5, 7.7],72% 流域为正 |
| 一年高**预测**流量覆盖 global→分层 CQR | 0.832→0.882;+5.0pp,流域/HUC2/同步年重采样下均正 |
| 稠密分布评分(13点 IQS,log1p 尺度) | MDN 0.077511、高斯头 0.078314、噪声MC 0.081902;解析 CRPS 0.080759 |
| 多水平反例 | 50% 原始覆盖 0.420(1年) vs 0.370(15年);TCN 过覆盖 0.930/0.922 |
| 匹配 365−180 天记忆 NSE 效应 | 短记录 +0.0002 [-0.0022,0.0070];长记录 +0.0072 [0.0002,0.0125] |

在不同重采样方案下，评分与点技巧的方向比原始覆盖稳定；不据此宣称
普遍的原始覆盖梯度。

## 目录结构

```
src/                    共享库层(data_preprocessing.py 也直接运行)
├─ evaluation/          评价协议:CQR 半径、区间评分、IQS、解析 CRPS、分组、空集投影
├─ models/              LSTM(LPU-Stream)、标准 LSTM、TCN
├─ heads/               稠密分布头(MDN、高斯、噪声)
├─ benchmark/           671 流域基准加载器
├─ corrections/         修正后稀缺实验共享加载器
├─ visualization/       训练输出图面板
├─ data/                CAMELS 读取、预处理、标准化
├─ losses/              pinball 损失、CQR 校准器
└─ utils.py             种子、哈希、设备工具

experiments/            运行层,每脚本一个职责
├─ prepare/             缓存构建/校验、数据链与检查点审计
├─ train_primary/       主 12 拟合(队列驱动)、互斥子集、端点复跑
├─ train_benchmark/     点模型与 671 流域八种构造、13 分位数稠密导出
├─ bias_correction/     中位数偏差修正诊断
├─ train_sensitivity/   48 个端点拟合(队列驱动)
├─ evaluate/            方法比较、逐成员 split-CQR、覆盖、评分、校准变体、无资料流域迁移
├─ analyze/             汇总、配对效应、代表性、学习曲线
└─ figures/             论文全部图

run_pipeline.py         唯一总入口,按阶段顺序调度
download_camels.py      下载 CAMELS-US 数据档案
tests/                  协议单元测试(无需数据集)
configs/                数据配置
```

依赖是单向的:`run_pipeline.py` 调用 `experiments/` 下的脚本,脚本再从
`src/` 导入共享逻辑;脚本之间不互相 import。

## 复现

```bash
pip install -r requirements.txt
python download_camels.py
python src/data/data_preprocessing.py
python run_pipeline.py --list      # 查看阶段
python run_pipeline.py --dry-run   # 只解析脚本路径,不运行
python run_pipeline.py             # 全量重跑(阶段 2/3/5 需要 CUDA GPU)
python -m pytest tests -q          # 协议测试
```

参考环境:Python 3.11、PyTorch 2.11.0+cu128、RTX 5060 Ti(8GB);见
`requirements-reference-cu128.txt`。数据、权重与逐样本预测不入库,各阶段在
`results/` 下重建产物;冻结发布包及其 SHA-256 哈希见
[REPRODUCIBILITY.md](REPRODUCIBILITY.md)。
